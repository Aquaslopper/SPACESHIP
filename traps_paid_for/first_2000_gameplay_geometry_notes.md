# First 2,000 HTA lines — gameplay and true geometry notes

## What this document means

This is a source-to-port review, not a patch. **No game code, data, assets, builds, or existing notes were changed to produce these notes.** The accompanying `first_2000_line_ledger.csv` accounts for each physical HTA line from 1 through 2000, including comments and declaration continuations. The embedded JPEG payload is represented by its byte count and SHA-256 instead of printing base64.

**Status key**

- **PRESENT** — the stated mechanism or value has an identifiable implementation in the inspected native code. This does not mean it has been proved correct through a live play session.
- **PARTIAL** — an implementation exists, but a specific part differs or is missing.
- **MISSING** — the inspected corresponding native path does not implement the stated feature.
- **UNVERIFIED** — available evidence does not justify a yes or no; no replacement rule is invented.
- **PLATFORM** — browser/HTA implementation detail; compare its purpose, not its syntax, with the native program.

The user's corrections remain authoritative: the green mark is feedback for a **positive click**; a free inspection is not automatically a defect because it displays that mark. Native text has an approved **18 px minimum**. The approved five-other-committed-action cooldown is not to be removed in pursuit of literal CSS parity.

Only HTA lines 1–2000 supply source rules here. Native functions were inspected where they implement those rules. This is a review boundary, not a claim that later game logic is irrelevant or forbidden to review in future.

### Geometry findings that are definite from code, not guesses about appearance

1. **Content bottom gap:** HTA 23; native calculation 22.
2. **Navigation column allocation:** source 214/252 INCLUDE their 12 px padding; native 214/252 panels PLUS 12 px gaps.
3. **Navigation centre group:** source centred in remaining width; native fixed left origin after width cap.
4. **Under-chart cards:** source 49% / 2% / 49%; native halves with a fixed 6 px gap.
5. **Target-action row:** source centred; native starts at left edge.
6. **Large lens:** data 290×160 with elliptical CSS; native paints width-based circle.
7. **Asymmetric hull radii:** source preserves flat attachment sides; generic native rounded rectangles do not.
8. **Normal room system labels and small instrument glyphs:** omitted from native deck-plan paint path.
9. **Room heroes:** implemented, but generic/simplified—not missing altogether. In particular, their per-room accent and variant geometry are not fully painted.
10. **Feed:** native whole-content scrolling does not implement the feed's own scrolling.

These are notes, not authorization to change any of those features. The approved 18 px floor is not revoked by this list.

## C. Questions and limits — do not silently decide these

**A. Oxygen charge units:** line 1888 comments `lifeMax:200` as a full charge 'in actions', while line 1889 drains 4 per action. Native code follows both literal numbers, so uninterrupted charge lasts 50 drain ticks. Is that intended? No number was changed or proposed as a correction here.

**B. None-job training / air versus fixed-price orders:** declarations alone do not settle handler fallback/precedence. Keep existing behaviour until compared with the actual corresponding HTA functions or clarified by the user. No new rule is inferred.

**C. Rendering evidence:** this review inspected code, not a fresh GPU screenshot or live-play recording. PRESENT means implementation identified; it does not certify pixel parity or every possible game path. The per-line ledger deliberately repeats multi-line rule IDs across continuations rather than falsely asserting that each line is an independent tested mechanic.
