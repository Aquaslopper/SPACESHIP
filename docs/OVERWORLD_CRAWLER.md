# PC-98 Overworld Planet Crawler — Technical Summary

> **Status note:** This document describes the current implementation as of `2026-11-26` on `arena/b3d08682-spaceship` (the B1..B3 crawler) for technical reference only. Per `AGENTS.md`, the game is in active Beta—none of the mechanics below are permanent requirements, and this file never overrides the repository owner's instructions.

This document explains how the first-person PC-98-style planet exploration mode ("Dispatch") works across simulation state, Bridge UI integration, deterministic surface and underground generation, and the `480x288` software pixel rasterizer.

---

## 1. High-Level Flow & Design Constraints

1. **Arrival & Landing (`cpp/core/Navigation.cpp`)**
   - When the ship arrives at a body, `Simulation::ArriveAt` sets `map_.inSpace = false` and `map_.here = body->id`. Departing via `Simulation::StartTravel` sets `map_.inSpace = true`.
   - Landing state is derived by `Simulation::LandedOnPlanet()` (`!map_.inSpace && here != nullptr && here->type == "planet"`).
   - `state_.docked` is set by `ArriveAt` only when `HerePort()` matches the arrival body. `SaveSystem.cpp` (`Simulation::ValidSave`) rejects saves where `state_.docked == true` without a matching port in `catalog.FindPort(here)`.

2. **Bridge Integration (`cpp/ui/RoomsScreen.cpp`, `cpp/ui/Widgets.cpp`, `cpp/ui/Draw.cpp`)**
   - `BuildRoomScreen(sim, "bridge")` inserts an action row (`id = "dispatch"`, `label = "Dispatch"`, `cost = "free"`) between `"fuel-split"` and `"warp"` whenever `sim.LandedOnPlanet()` is true.
   - `Widgets.cpp` sets `hideCost = true`, `charged = false`, and `actionCost = false` on `"dispatch"` so it renders without a click/charge badge and never enters the command charge system.
   - In `PaintPanelsScreen` (`cpp/ui/Draw.cpp`), `"Dispatch"` occupies the center Command Bay socket (`midBtnW = 82.0f * scale`, `x = stageX + 439.0f * scale` when present, auto-fitted label, terracotta when closed / amber when open).
   - Clicking `"dispatch"` in `ShellView::Click` sets `bridgeDispatch_ = true` directly in the view layer, resets `contentScroll_`, clears floating panels, and calls `EnsurePlanetSurface(sim)` without advancing the simulation clock (`PressRoomAction(sim, "dispatch")` simply returns `sim.LandedOnPlanet()`).
   - While dispatch is active on the Bridge tab, `ShellView::BlockerActive` is true and `ShellView::DrawBlocker` (called from `cpp/app/main.cpp` after `rlImGuiEnd()`) draws `assets/art/blocker.png` scaled so its transparent cutout (`x = 319..1767`, `y = 131..672` in the 1920x1078 source) aligns with `bridgeBlockerHole_`. `Move`, `Drag`, `Scroll`, and `Click` return early for input outside that hole. Clicking the landed ship on the surface (hit kind `6`) sets `bridgeDispatch_ = false` and dismisses the blocker.

3. **Persistence (`Simulation::CollectPlanetOre` in `cpp/core/Navigation.cpp`)**
   - Walking, turning, and mine traversal live in UI view state (`ShellView::planetSurface_`) and cost zero clicks.
   - Collecting an ore package writes a persistent mark into `state_.mapMarks`:
     - Key: `"planet-ore:" + planetId + ":" + std::to_string(oreIndex)`
     - If unmarked and cargo space allows (`CargoUsed() + CargoReserved() + 1.0 <= cargo_.capacity`), appends a `1.0 m3` `GoodsLot` named `"Planetary Ore (" + body->name + ")"` (`kind = "Bulk metal"`, value `28..45` derived from `MapEventHash(markKey)`), logs to the feed, and sets `mapMarks[markKey] = true`.
     - Ore indices `0..oreCount-1` are shared across the surface and underground layers (see `oreLayerMask` in section 2); the same key space serves both layers with no save-format change.
   - Dungeon state (`Simulation::Dungeon*` in `cpp/core/Navigation.cpp`) writes only `state_.mapMarks` under `planet-dng:<planetId>:f<N>:<what>` where `N` is `1..3` and `what` is `gate`, `lever`, `door:<i>`, `trap:<i>`, `mob:<i>`, or `chest:<i>`, plus `planet-dng:<planetId>:monolith` for the B3 survey monolith. `LoadPlanetLayer` re-derives every floor from its seed and re-applies these marks on each entry, so a save reload restores opened bulkheads, the raised portcullis, sprung hazards, sentry HP, looted vaults, and the filed monolith with zero save-format change. Crew damage is real: health floors at exactly `0.0` and `CheckLoss()` erases the hand; there is no reset on travel, dock, save, or load.

## 2. Surface State & Procedural Generation

Defined in `cpp/ui/Draw.h` (`ShellView::PlanetSurfaceState`), built by `ShellView::LoadPlanetLayer(const Simulation& sim, std::uint8_t targetInMine, bool placeOres)` and `ShellView::EnsurePlanetSurface(const Simulation& sim)` in `cpp/ui/Draw.cpp`:

- **Grid dimensions:** `kSize = 16` (`16x16` tiles), `kSizeShift = 4`, `kViewSize = 9`, `kMaxOre = 5`, `kTexW = 480`, `kTexH = 288`.
- **Packed cells:** `cells[256]` stores one byte per tile: bits `0..1` = tile, bits `2..4` = deterministic visual variant (`0..7`), addressed as `(y << kSizeShift) | x` via `Tile()`, `Variant()`, `SetTile()`, and `SetVariant()`.
- **Tile values (`Tile()`):**
  - `0` — Open walkable ground
  - `1` — Impassable obstacle, wall, or outer map border
  - `2` — Ship landing pad at `(8, 14)` (surface layer only)
  - `3` — Carved trail (surface) or mine rail path (underground layer)
- **Player state:** `px`, `py`, `dir` (`0=N, 1=E, 2=S, 3=W`), spawn at `(8, 13)` facing North on the surface. `inMine` selects the active layer (`0` = surface, `1` = underground mine). `surfPx`, `surfPy`, and `surfDir` save the surface position and heading while underground. `portalX`, `portalY`, `portalOutDir`, and `mineInDir` describe the active layer's portal cell and its outward and entry headings.
- **Deterministic seeding:** `LoadPlanetLayer` computes a 32-bit FNV-1a hash of `here->id` (`2166136261u` basis, `16777619u` prime) XORed with `sim.World().chartSettings.seed * 2654435761u`. Each layer steps its own Xorshift32 generator (`nextRand()`) from that seed; the underground layer XORs the seed with `0x85EBCA6Bu` first. Re-opening Dispatch or re-visiting the same planet regenerates the exact same layouts.
- **Surface generation steps (`targetInMine == 0`):**
  1. Outer perimeter (`x == 0 || x == 15 || y == 0 || y == 15`) is initialized to `1`; interior to `0`. Ship pad `2` is placed at `(8, 14)`.
  2. `24..32` interior obstacles (`1`) are placed while keeping `(8, 14)`, `(8, 13)`, and `(8, 12)` clear. Each placement is verified with the BFS `connectedFrom` check (treating `1` and `2` as solid) so every walkable tile remains reachable from `(8, 13)`.
  3. A main winding trail (`3`) is walked from `(8, 13) -> (8, 12)` for `22..30` steps (favoring turns over long straight runs and avoiding 2x2 blobs via `countAdjTrail`), followed by `3..5` curving side branches (`5..9` steps each).
  4. `variant` for all 256 cells is populated with `nextRand() & 7u`. Surface obstacle variants split by bit 2: `0..3` select biome prop and forest models, `4..6` select sloped mountain models, `7` selects vertical stone masonry and the mine portal cell.
  5. One enterable mine portal is selected from the obstacle cells facing a reachable `0` or `3` approach tile at Manhattan distance `>= 4` from the ship pad, preferring interior cells backed by another obstacle or border and adjacent to the trail (tier 1), then other interior cells (tier 2), then border cells (tier 3). The portal cell keeps tile `1`, its variant is set to `7`, and its approach tile is set to `3` when open.
- **Underground generation (depths B1..B3, `targetInMine` 1..3):** three separate 16x16 floors, not one mine.
  1. **Seeding.** The per-floor seed is `FNV-1a(planetId)` XOR `chartSettings.seed * 2654435761u` XOR `(targetInMine * 0x9E3779B9u ^ 0x85EBCA6Bu)`, stepped through Xorshift32 (`nextRand()`). Every floor therefore differs from its neighbours and from every other planet, yet regenerates identically byte for byte on any re-entry, save reload, or re-open of Dispatch.
  2. **Masonry.** All 256 cells start as `1` (rock). Each floor places `3..5` chambers of `3x3..5x4` carved to tile `0`, entering each `4x4`/`5x4` chamber with a `1x1` pillar (variant `7`); `1`-tile corridors are carved at tile `3` between chamber centres, with `1..2` secondary loops so no route is a single hallway; and `2..3` dead-end vault alcoves are carved as a threshold (`2`) plus a 1x1 end chamber (`0`) behind solid rock. Walls receive variants `4..7`.
  3. **Alcove guarantee.** If random carving cannot place `2..3` alcoves, a deterministic exhaustive top-up tries every open cell against every cardinal direction (two-tile passage first, then one-tile), then falls back to dressing a chamber wall cell as the threshold with the rock behind it as the vault end. That is what guarantees the locked portcullis vault.
  4. **Stairwells.** A stairwell is a solid wall cell with exactly *one* open approach tile (all candidates collected in one pass). B1's ascent *is* the surface portal (`portalX/Y = stairX/Y[0]`, `shaftX/Y = stairX2/Y2[0]`), placed at the vestibule head with a Manhattan distance of `>= 6` from the descent. B2 carves both an ascent and a descent; B3 carves an ascent plus the Core Vault monolith.
  5. **Bulkheads.** `2..3` per floor: alcove mouths first, then straight choke points on a chamber ring, then a deterministic chamber-threshold pass. Each is a `2` threshold tile. On the floor the mark `planet-dng:<pid>:f<N>:door:<i>` opens it permanently.
  6. **Portcullis + lever.** Exactly one locked portcullis per floor: it is the *first* alcove mouth (`gateX/gateY`). The wall lever is a solid, dressed-stone wall cell (never a stair arch, vault mouth, bulkhead or monolith bracket) picked from the same candidate pool, with its approach tile facing it.
  7. **Connectivity passes (`LoadPlanetLayer`).** All reachability is a stack BFS - `std::uint16_t reachRows[16]` as a per-row bitmask plus a `std::uint8_t queue[256]`, `0 B` heap. Pass 1 walks from the floor spawn with bulkheads *openable* but the portcullis shut, and re-picks the lever if its approach is unreachable. Pass 2 re-walks with the portcullis raised and re-picks the descent stair, the monolith (B3) and drops any chest / ore whose approach is unreachable. A final check treats each solid chest/ore as an obstruction and drops it if that would cost more than one reachable tile - a full hold can never make a floor unwinnable. Portcullis, ascent and descent are also kept off each other's cells.
  8. **Entities.** `2..4` biome-keyed hazard plates (magma grate / cryo spike bed / brine vent / dart grille / spore fissure chosen from the planet's subtype and class), at least 3 tiles from the entry and never on a door, stair, arrival or vault tile; `1 / 2 / 2..3` sentries by floor, all at Manhattan `>= 4` from the entry; `1 / 2 / 2` vault chests (B1 has one, deeper floors up to two, all inside sealed alcoves); B1-only mine ore; the B3 monolith is mounted in a reachable chamber wall at `>= 3` from the ascent.
  9. **Rotation.** The whole floor is written through `mapCoord(u,v)` rotated by `mineInDir`, so the B1 daylight shaft lines up with the surface portal's heading while every other fixture rotates with it. Variants are assigned on write: stair cells and pillars get `7`, other walls `4..6`, floors `0..7`.
  10. **Layer assembly.** `EnsurePlanetSurface` builds the surface with ore placement, snapshots `cells[256]` and the portal fields, builds B1 once (to allocate the underground ore indices), then restores the surface grid in place. No second persistent grid exists.
- **Ore placement:** The per-planet total is `3..5` (`totalOreGoal`), split into `2..3` surface ore (`surfOreGoal`) and `1..2` mine ore (`mineOreGoal`). `oreLayerMask` bit `i` records the layer of ore index `i` (`0` = surface, `1` = mine). Surface candidates are `0` or `3` tiles with Manhattan distance `>= 3` from the ship pad, excluding the spawn and portal approach tiles; mine candidates are B1 carved `0` or `3` tiles at Manhattan `>= 5` from the entry, excluding stair, bulkhead, portcullis, chest, hazard and alcove-end cells. Each accepted placement must preserve `connectedFrom` for its layer and leave every placed ore of that layer adjacent to at least one reachable walkable tile (so uncollected crates never seal a choke point when the cargo hold is full).
- **Layer assembly:** `EnsurePlanetSurface` resets `PlanetSurfaceState`, loads the surface with ore placement, copies `cells[256]` and the surface portal fields aside, loads the mine with ore placement (continuing the same ore index sequence), then restores the surface cells and portal in place and spawns the player at `(8, 13)`. No second persistent grid is stored. Stepping forward into the portal from its approach tile (`StepPlanetSurface`) regenerates the destination layer in place with `placeOres = false` and restores the saved surface position on exit; heading stays continuous through `portalOutDir` / `mineInDir`.

## 3. Software Pixel Renderer (`480x288`)

`ShellView::RenderPlanetSurfacePixels(const Simulation& sim)` in `cpp/ui/Overworld.cpp` rasterizes the first-person viewport into a static 8-bit indexed framebuffer (`idxBuf[480 * 288]`, `138,240 B` static BSS, `0 B` heap) and uploads it to `planetTex_` (`TEXTURE_FILTER_POINT`):

- **Dirty-check caching:** Rasterization and texture upload are skipped unless `(planet hash, px, py, dir, inMine, oreMask, dungeonSig)` changes. `dungeonSig` is an FNV-1a fold (seed `14695981039346656037`, mix `v + 0x9E3779B97F4A7C15 + (sig << 6) + (sig >> 2)`) over the floor number, gate/lever/monolith flags, every bulkhead/trap/chest open bit, every sentry's position + HP, and the `exploredRows` fog bits; it is `0` on the surface. Because a fixture cannot change without the player moving (already part of the key), the cache never serves a stale fixture frame. `oreMask` is a bitmask of uncollected ore indices derived from `sim.State().mapMarks`; it is recomputed only when the planet hash, `mapMarks.size()`, or `state_.lotSerial` changes. `ShellView::ReleaseGraphics()` guards `UnloadTexture(planetTex_)` and `UnloadTexture(planetScanlineTex_)` with `IsWindowReady()`.
- **Palette resolution & upload:** The indexed buffer is resolved through `resolvedLut[72]` (26 base colors plus pre-quantized mid-fog and silhouette-ink entries) in 16-row strips (`Color stripRgba[480 * 16]`) via `UpdateTextureRec`. A `1x1152` scanline texture (`planetScanlineTex_`, alpha profile `{18, 0, 14, 88}` per source row, `TEXTURE_FILTER_BILINEAR`) is built once and drawn over the viewport by `PaintStage`.
- **5 Biome Palettes, 20 Sub-Biomes:** The base biome is detected from `planet->subtype` and `planet->klass` with precedence lava, ice, ocean, rock, temperate:
  1. `ice` (`subtype == "ice"`)
  2. `ocean` (`subtype == "ocean"`)
  3. `lava` (`subtype == "lava"` or `klass` contains `Lava`/`Volcanic`/`lava`)
  4. `rock` (`subtype == "rock"` or `klass` contains `Rugged`/`Barren`/`Crater`)
  5. `temperate` (default)

  A deterministic per-planet seed derived from the planet ID hash and chart seed selects `subBiome` (`0..3`), `celestialKind`, `cloudStyle`, `horizonStyle`, `roadStyle`, and `propBias`. Palettes are 20 nibble-packed 12-bit `RGB4` entries sets (`kBiomePalettes[20][24]`, `480 B`, verified via `static_assert`) of 16 colors each, plus a shared 10-entry `RGB4` sprite bank (`15 B`, indices `16..25`: star/cloud tones, ship hull and visor, ore crate). All output pixels are multiples of 17 per channel. `airlessWorld`, `nightSky`, and `duskSky` are derived from biome and sub-biome.
- **Sky, Dithering & Horizon:**
  - `hy = 138` (`69 * kResScale`, `kResScale = 2`) separates sky (`0..137`) and ground (`138..287`, `kGndH = 150`).
  - Sky and ground gradients use 4x4 Bayer ordered dithering (`kBayer4[4][4]`) and `#0a0b0f`-equivalent index `0` (`inkOut`) 1px silhouettes on clouds and horizon ridges.
  - Surface sky passes draw a density-tiered starfield, aurora curtains on ice sub-biome `1`, one of four compass-parallax celestial landmarks (ringed gas giant, cratered moon, coronal/binary sun, twin moons), cumulus or stratus cloud banks, two-layer parallax horizon ridges with biome landmarks, and lava caldera smoke plumes. Underground, the sky region is replaced by a foreshortened stone cavern ceiling with timber rafters, stalactites, and a daylight exit shaft at the portal.
  - Depth fog uses the constexpr scanline LUT (`kScanLut`, one `z` / `invScaleX` / `fogStep` entry per ground scanline) and per-depth steps (`kDepthFog[7]` on the surface, `kMineDepthFog[7]` underground, fog target `sky3` on the surface and `inkOut` underground) through two-band 4x4 Bayer transitions in index space. Silhouette inks stay `inkOut` at `d = 0..3` and step toward the fog target at `d = 4..6`.
- **True `1 / z` First-Person Pinhole Projection & Full-Tile Road:**
  - Ground scanlines (`y = hy..H-1`) project forward depth as `z(y) = kProjY / ((y - hy) + 0.5f)` via `kScanLut` (`kProjY = 66.0f`, `kProjX = 252.0f` at `kResScale = 2`, ~88° horizontal FOV) with camera eye inside `d = 0`.
  - Path tiles (`tile == 3` and ship pad `2`) are rasterized as full-tile roads (`kHalfRoad = 0.44f`, extending seamlessly across connected road neighbors, with beveled convex corners and aligned inner L/T-junction curbs) by an integer `16.16` fixed-point DDA trapezoid rasterizer over visible road spans only: curb pass, sentinel interior pass, then world-anchored shading with step-parity checkerboard dither and perspective-anchored texture. Surface roads sample the `32x32` cobblestone tile sheet (`kCobbleRoadTex`, 128 texels per tile) with per-biome and `roadStyle` variations (frost boardwalks, flagstones, ember-seamed basalt, rutted gravel/dirt); underground paths render as minecart rails with wooden sleepers. Off-road open terrain (`tile == 0`) remains freely walkable.
  - Three compile-time `32x32` tile sheets (`kStoneWallTex`, `kCobbleRoadTex`, `kCragRockTex`, `3 KB` total) provide the stone masonry, cobble, and crag textures, with per-cell mirror/jitter on crag sampling.
- **Occlusion Prepass:**
  - A front-to-back pass (`d = 0..6`) maintains horizontal clip bounds `[xlower, xupper]`, a per-depth column occlusion mask (`depthColOcc[7][15]`), and a stack bitset (`vis[2]`, `16 B`) covering the 77 frustum cells (`d = 0..6`, `|s| <= d + 2`).
  - Full-height occluders narrow the clip bounds and mark occluded columns: underground walls at `d <= 5`, a **closed** bulkhead at any `d` (a sealed riveted door is a full-height wall; an opened bulkhead and the portcullis — drawn as real bars with see-through gaps — never occlude), surface masonry at `d = 1..2` with `cliffTopScaleFor >= 0.85f`. When the bounds seal, `viewSealed` stops the pass and, underground, the fully overwritten ceiling and floor scanline bands are skipped.
- **Painter's Algorithm & Full-Tile Obstacles:**
  - Visible cells are drawn back-to-front (`d = maxVisD` down to `0`, outer-to-inner across `s`) using the same `yAtZ`, `halfTileAtZ`, and `tileCenterAtZ` `1 / z` helpers, culled by `vis[2]`, `rowX0[d]` / `rowX1[d]`, and `depthColOcc[d]`.
  - **Surface obstacles (`1`):** The portal cell draws `drawCaveMoundPortal` (domed craggy mound with timber-framed entrance). Variants `4..6` draw `drawMountainCell` (wide-based sloped craggy mountains, base skirts only toward adjacent blocking tiles). Variant `7` draws `drawCliffCell` (vertical stone masonry with unified connected rooflines and perspective merlons on fortress runs). Variants `0..3` draw biome prop and forest models (`drawForestGrove`, `drawBroadleafTree`, `drawPineTree`, `drawExoticCanopy`, `drawCrystalCluster`, `drawGlacialSerac`, `drawSeaStack`, `drawBranchingCoral`, `drawHydroVent`, `drawBasaltArch`, `drawSandstoneHoodoo`, `drawBandedButte`, `drawMossyMonolith`, `drawDesertSucculent`, `drawScrubBush`) distributed across the tile by `drawBiomeProp`, with border tiles drawing layered ridge and paired-prop compositions.
  - **Underground walls (`1`, variants `4..7`):** All draw `drawCliffCell` as World of Xeen-style chunky stone masonry, mineral veins, or shored timber bays with wall torches and barred alcoves, flush to the cavern ceiling. Only the exit portal cell draws the daylight shaft face.
  - **Open ground (`0`):** Draws low non-blocking scatter (`drawGroundScatter`) when `variant % 3 == 0` at `d = 1..4`.
  - **Interactive world objects:** Ship lander and uncollected ore crates of the active layer are drawn visually across the forward view cone (`d = 1..6`, `|s| <= d`), occluded by nearer cells through the painter's pass and occlusion bitset, and export a single unified normalized UV hit box (`planetSurface_.frontKind`, `frontArg`, `frontUv`) **only** when directly 1 tile ahead (`d == 1 && s == 0`): `frontKind = 6` (ship, surface only), `5` (ore), or `8` (portal/exit, from the portal cell at `d == 1 && s == 0` on its approach side).
  - **Dungeon fixtures (painter's pass, `d = 1..6`):** Each fixture is clipped by `rowX0[d]`/`rowX1[d]` and the per-column `depthColOcc[d]` mask and drawn at its own tile plane through `yAtZ`/`halfTileAtZ`/`tileCenterAtZ`:
    - Tile `2` bulkhead: `drawBulkhead` + `setFront(10, idx)` when closed (full-height occluder); open bulkheads draw nothing and never occlude.
    - Tile `2` portcullis (`gateX/gateY`): `drawPortcullis` + `setFront(11, gateOpen)`; raised when `gateOpen`, never an occluder.
    - Wall lever (solid wall cell at `leverX/leverY`): `drawLever` + `setFront(12, leverOn)` at `d == 1 && s == 0`.
    - Stairwells (solid wall variant `7`): `drawCliffCell` + `setFront(13, 0)` (ascent) / `setFront(14, 1)` (descent) at `d == 1 && s == 0`.
    - Floor hazards (`trapX/trapY`, `d <= 4`): `drawTrapPlate` + `setFront(15, trapIndex)`; armed plates draw their biome glyph (magma grate / cryo spikes / brine vent / dart grille / spore fissure), sprung plates draw spent.
    - Vault chests (`chestX/chestY`, `d <= 5`): `drawChest` + `setFront(16, chestIndex)`; opened chests draw empty.
    - B3 monolith (`monolithX/monolithY`, wall cell): `drawMonolith` + `setFront(17, monolithActive)` at `d == 1 && s == 0`.
    - Sentries (`mobX/mobY`, `d <= 5`): `drawSentry` + `setFront(18, mobIndex)` with `2..3` HP pips; dead sentries (`mobHp == 0`) draw nothing.

## 4. Bridge Monitor Overlay, Controls & Hit-Testing

Inside `ShellView::PaintStage` (`cpp/ui/Draw.cpp`):

- **CRT Shutter Animation:** `bridgeDispatchOpen_` eases between `0.0` and `1.0` (`3.6f * dt`, smoothstep-clipped with `BeginScissorMode` / `EndScissorMode`, or instantaneous when `sim.State().reducedMotion` is true).
- **Monitor Layout (`960x460` Bridge stage space):**
  - **Left (`118, 98`):** Legendless high-contrast `MAP` minimap (`MINE` underground), `mmCell = 14.0f`, showing a `9x9` edge-clamped scrolling window (`camX = clamp(px - 4, 0, 7)`, `camY = clamp(py - 4, 0, 7)`) over the `16x16` active layer: walkable floor, curbed golden `PATH` ribbon, biome obstacle blocks, cliff blocks, ship beacon (surface only, when inside the window), portal marker (amber on surface, cyan underground, when inside the window), and the double-outlined player directional arrow. Ore locations are intentionally omitted from the minimap so exploration relies on the 3D viewport. Underground the minimap is fogged: cells never marked in `exploredRows[floor][row]` draw as dark slate (`Color{26,29,35}`) and only explored fixtures are marked — cyan ascent, amber descent, lever, closed bulkhead/portcullis, unopened vault. `MarkDungeonExplored` marks the `3x3` around the player plus up to two tiles down an unoccluded sightline on every step, turn, and floor switch.
  - **Center (`275, 42, 410, 244`):** `planetTex_` scaled with `DrawTexturePro` with `planetScanlineTex_` drawn over it, plus a unified 1-tile-ahead (`d == 1, s == 0`) hover outline and dark-plated `"SHIP"` / `"ORE"` / `"MINE"` / `"EXIT"` tag derived from `frontUv`, and a framed PC-98 bump banner when attempting to step onto an occupied/blocked tile. Underground the tag reads `BULKHEAD` / `PORTCULLIS` / `LEVER` / `STAIRS UP` / `STAIRS DOWN` / `HAZARD` / `VAULT` / `MONOLITH` / `SENTRY` for `frontKind` `10..18`.
  - **Right (`700, 48..102` & `718, 136, 122, 122`):** Planet name, `DIR (x,y)` (or `MINE (x,y)` underground), remaining `ORE` count across both layers, next-tile `BLOCKED: ...` / `AHEAD: MINE` / `AHEAD: EXIT` status readout, and the 5-button D-pad (`Up`, `Down`, `Left`, `Right`, center `180`). Underground the title becomes `FLOOR N (x,y)` with `B1 UPPER WORKS` / `B2 UNDERCROFT` / `B3 CORE STRATA`, the panel adds lead `HP`, `KITS`, and `VAULTS open/total`, and the status line reads `AHEAD: BULKHEAD` / `BLOCKED: PORTCULLIS` / `BLOCKED: SENTRY` etc. for `bumpKind` `5..7`.
- **Input & Solid-Tile Blocking:**
  - **Movement (`StepPlanetSurface`):** Obstacles (`1`), the ship (`2`, surface only), and uncollected ore crates of the active layer block movement onto their tile and record `bumpKind` (`1=prop, 2=ship, 3=ore, 4=cliff/wall`) + `bumpBack` for status feedback; collected ore tiles revert to ordinary walkable ground. Stepping forward from the portal approach tile onto the portal cell traverses to the other layer instead of bumping; stepping backward does not traverse. Underground every fixture occupies its tile: closed bulkhead (`5`), closed portcullis (`6`), and a living sentry (`7`) block with their own `bumpKind`; bumping forward into a sentry trades blows (`strikeMob`). Stepping onto an armed hazard trips it (`ActivateDungeonTrap` → `Simulation::DungeonTriggerHazard`); stepping onto a sprung plate is safe. Stair cells block as walls (`4`) — crossing them needs an interact.
  - **Interact (`actionKind == 9`):** `E` / `Space` (or a click on the 1-tile-ahead fixture) calls `StepPlanetSurface(sim, 9)` → `interactFront()`, which resolves the tile directly ahead in order: unopened chest (`DungeonLootChest`), living sentry (`DungeonStrikeSentry`), unthrown wall lever (`DungeonClaimLever` — raises the portcullis), closed portcullis (force-breach with `1` repair kit via `DungeonForceGate`, or a log hint when kits are empty), closed bulkhead (writes `planet-dng:<pid>:f<N>:door:<i>` and opens permanently), unfiled B3 monolith (`DungeonFileMonolith`), ascent/descent stairs (`takeStairs`), and armed hazard (jam with `1` repair kit, else trip it). `actionKind == 8` (portal click) traverses the portal when facing it from its approach tile, otherwise falls through to `interactFront()`.
  - **Sentries:** `TickDungeonSentries()` runs after every step, turn, interact, and floor switch underground. Each living sentry moves exactly one grid step per tick toward the player (greedy axis step, closed bulkheads/raised portcullises solid, never onto stairs or another sentry). Striking deals `1 + 1` (apt role/skill) `+ 1` (lead alive) damage; the counter-blow is `6 + ((mobIndex * 3 + floor * 4) % 9)` health and `4 + floor` fatigue. Defeat pays `12 + (hash % 17)` shiplets plus a deterministic cache (`repairKits` / `fuelCells` / shiplets by `hash % 7`).
  - **Hazards:** `8 + 4*floor` health and `6 + 2*floor` fatigue to the away lead (`DungeonLead`: `crewSel` when aboard and alive, else first living hand, else the hull takes half). Vent kinds (`2` brine, `4` spore) also drain `1.5` `airHold`. With no living hand aboard, the hull takes the blow instead.
  - **Keyboard (`PaintStage`):** `Up`/`W` (`1`, step forward), `Down`/`S` (`2`, step back), `Left`/`A` (`3`, turn left 90°), `Right`/`D` (`4`, turn right 90°), `R`/`X` (`7`, turn 180°) call `StepPlanetSurface(sim, kind)`; `E` / `Space` calls `StepPlanetSurface(sim, 9)`.
  - **Mouse (`ShellView::Click`):** `planetHits_` (`std::array<PlanetClickHit, 16>`) stores screen-space hit boxes for D-pad buttons (`1..4, 7`), the 1-tile-ahead ore crate (`5`, calls `sim.CollectPlanetOre`), the 1-tile-ahead ship (`6`, sets `bridgeDispatch_ = false`), and the 1-tile-ahead portal (`8`, calls `StepPlanetSurface(sim, 8)`), and the 1-tile-ahead dungeon fixtures (`10..18`, call `StepPlanetSurface(sim, 9)`). While `BlockerActive` is true, clicks outside `bridgeBlockerHole_` are rejected before hit testing.
